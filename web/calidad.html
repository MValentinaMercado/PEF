Análisis de calidad con SonarQube

SonarQube Cloud analiza el código desde el pipeline de integración continua: detecta bugs, vulnerabilidades, puntos críticos de seguridad, code smells y duplicación, y mide la cobertura. El Quality Gate es el conjunto de condiciones que debe cumplir el código nuevo; con sonar.qualitygate.wait=true el pipeline espera su resultado. Esta ventana no analiza nada: consulta el último análisis.

Métricas del proyecto

Corresponden al último análisis de SonarQube, no a una medición local ni necesariamente a la última corrida de CI.

Cómo está configurado

El proyecto se identifica en sonar-project.properties (organización y clave, que no son secretas). El pipeline (.github/workflows/ci.yml) genera coverage.xml con pytest --cov y ejecuta el análisis con la action oficial. El token no está en el repositorio: se guarda como secret SONAR_TOKEN de GitHub.

El mismo pipeline ejecuta, en etapas separadas: Gitleaks (secretos); Ruff, mypy, Vulture, Pylint, Radon y Bandit; pytest con cobertura mínima del 80 % junto con SonarQube; pip-audit, MkDocs, Sphinx y Lychee; y, solo si todas aprobaron, los controles de rendimiento y memoria. Sin SONAR_TOKEN (por ejemplo, en Pull Requests desde forks) el análisis de SonarQube se omite. Los resultados de limpieza de código se ven en la ventana Optimización.

Pipeline de integración continua (GitHub Actions)

El pipeline .github/workflows/ci.yml ejecuta los controles y decide si el código se aprueba. Esta ventana no los ejecuta ni los simula: lee de GitHub el resultado real de la última corrida en main.
