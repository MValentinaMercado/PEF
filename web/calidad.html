Análisis de calidad con SonarQube

SonarQube Cloud analiza el código en cada push y en cada Pull Request del pipeline de integración continua. Detecta bugs, vulnerabilidades, puntos críticos de seguridad, code smells (código difícil de mantener) y duplicación, y mide la cobertura de las pruebas. El Quality Gate es el conjunto de condiciones que el código nuevo debe cumplir: si alguna falla, el pipeline falla. Esta ventana no analiza nada: muestra el resultado del último análisis.

Cómo está configurado

El proyecto se identifica en sonar-project.properties (organización y clave del proyecto, que no son secretas). El pipeline (.github/workflows/ci.yml) genera coverage.xml con pytest --cov, ejecuta el análisis con la action oficial de SonarQube y, con sonar.qualitygate.wait=true, espera el resultado del Quality Gate. El token de acceso no está en el repositorio: se guarda como secret SONAR_TOKEN de GitHub.

Antes de SonarQube, el mismo pipeline ya exige Ruff (calidad y formato), mypy, Vulture, Pylint (código repetido), Radon (complejidad), Bandit, Gitleaks y pip-audit (seguridad), una cobertura mínima del 80 % y los controles de rendimiento y memoria. Los resultados de limpieza de código se ven en la ventana Optimización.
