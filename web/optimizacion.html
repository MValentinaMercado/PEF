Criterio para optimizar

Una optimización solo vale la pena cuando una medición muestra un problema real. Se mide dónde está el costo (cProfile por función, line_profiler por línea, memory_profiler y Scalene para memoria), se modifica esa parte y se vuelve a medir en condiciones comparables. El pipeline bloquea regresiones con el Performance Gate y el Memory Gate (rutas/performance_gate.py y rutas/memory_gate.py). Los valores concretos pertenecen a cada ejecución: están en la ventana Análisis y en los registros de GitHub Actions.

Decisiones de no optimizar

La búsqueda de una sola ruta no se paraleliza. Los hilos no aceleran trabajo de CPU en Python por el GIL, y los procesos pagan el arranque del pool y la copia del grafo, por lo que solo pueden ganar con varios núcleos libres y muchas consultas. La ventana Análisis mide las tres estrategias con las mismas consultas para decidir con datos.
